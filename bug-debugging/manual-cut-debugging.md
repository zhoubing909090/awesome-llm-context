# Bug 排查场景：手动截断 + 首尾保留策略

## 策略简介

Bug 排查的核心挑战是：你会尝试多种假设，很多假设最终会被推翻，但这些被推翻的讨论仍然残留在上下文中，持续干扰模型。手动截断策略可以"隔离"被否定的方向，让模型在干净的上下文中继续排查。

## 适用场景

✅ **什么时候用这个策略：**

- 复杂 Bug 排查，需要验证多个假设
- 排查过程中某个方向被否定，需要换方向
- 对话中混入了大量试探性的、已被推翻的分析
- 需要保留问题背景，但排除无效探索路径
- 排查时间跨度大（可能持续几小时甚至几天）

❌ **什么时候不建议用：**

- 简单 Bug，三五轮对话就能定位（没必要用）
- 所有线索相互关联，不能孤立看待（建议用全量上下文）

## 策略配置

### 阶段一：初步探索 — 全量上下文

```json
{
  "strategy": "full",
  "note": "初步收集信息阶段，保持完整上下文"
}
```

排查初期，先把现象、日志、环境信息都告诉模型，完整上下文有助于模型全面理解问题。

### 阶段二：验证假设 — 手动截断

```json
{
  "strategy": "manualCut",
  "cutPoint": 15,
  "mode": "recoverable",
  "includeHead": 3
}
```

**参数说明：**
- `cutPoint: 15` — 在第 15 条消息处设置截断点
- `mode: "recoverable"` — 可恢复模式，后面可能还需要参考
- `includeHead: 3` — 保留前 3 条消息（问题描述、环境信息等核心背景）

**什么时候设置截断点：**
- 某个假设被彻底否定，确认方向错误
- 某段探索偏离主题，跟当前问题关系不大
- 排查进入新阶段，前面的讨论已经用不上了

### 阶段三：深入分析 — 首尾保留

```json
{
  "strategy": "headTail",
  "headReserve": 5,
  "tailReserve": 8,
  "middleStrategy": "collapse"
}
```

**参数说明：**
- `headReserve: 5` — 保留头部 5 条（问题背景 + 核心现象）
- `tailReserve: 8` — 保留尾部 8 条（当前排查方向的最新进展）
- `middleStrategy: "collapse"` — 中间内容折叠不发送

当排查进入深水区，头部的问题背景和尾部的最新进展最重要，中间的探索过程可以裁剪。

## 使用技巧

### 1. 截断时机的判断

| 信号 | 该不该截断 | 操作建议 |
|------|-----------|---------|
| 模型反复引用已被否定的假设 | ✅ 该截断 | 设为可恢复模式，万一后面有用还能调回来 |
| 排查方向完全转变（如从前端转到后端） | ✅ 该截断 | 保留问题背景，截断中间的错误方向讨论 |
| 只是讨论了一些细节但还没定论 | ❌ 先别截 | 等结论明确了再说 |
| 模型开始重复之前的分析 | ⚠️ 考虑截断 | 可能是上下文冗余的信号 |

### 2. 多假设排查的最佳实践

```
第1步：全量上下文，描述问题现象
第2步：假设A，讨论10轮 → 被否定
       ↓ 在第10轮设截断点（可恢复）
第3步：假设B，讨论8轮 → 部分正确
       ↓ 保留B的关键发现，切换为首尾保留
第4步：假设C，基于B的发现继续深入
       ↓ 最终定位根因
第5步：切换全量上下文，整理完整排查报告
```

### 3. 给截断点加标签

在设置截断点的那条消息里，可以写一句话标记截断原因，方便日后回溯：

> "【截断标记：排除了连接池泄漏的假设，问题不在这一层】"

## 效果案例

### 用户案例：线上接口超时排查

**背景：** 某电商平台支付接口在高峰期超时，涉及数据库、缓存、消息队列三个模块，排查过程复杂。

**使用前：**
- 排查 2 天，对话 47 轮
- 模型反复在三个模块之间跳来跳去
- Token 消耗：约 28,000
- 中间有 5 次需要重新纠正模型方向
- 最终定位问题，但花了很长时间

**使用手动截断+首尾保留后：**
- 排查 1 天，对话 32 轮
- 每个假设验证完就截断，上下文始终干净
- Token 消耗：约 11,200（节省 60%）
- 模型无明显跑偏，每次回答都聚焦当前方向
- 排查效率提升约 50%

**关键节点：**
1. 假设数据库连接池问题 → 讨论 12 轮 → 排除 → 截断
2. 假设缓存雪崩问题 → 讨论 8 轮 → 确认是主因 → 保留，切换首尾保留
3. 深入分析缓存策略 → 讨论 12 轮 → 定位根因 → 切换全量整理报告

**用户评价：**
> "以前排查复杂 Bug，对话越长越乱，AI 经常把已经排除的原因又拿出来说。有了手动截断之后，每个方向试完就'关门'，模型始终在正确的轨道上，效率提升太明显了。"
