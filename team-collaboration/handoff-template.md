# 团队协作场景：手动截断 + 交接模板策略

## 策略简介

团队协作中，上下文管理的痛点不一样——不是跑偏的问题，而是"交接"的问题。一个人跟 AI 讨论了半天，另一个人接手时完全不知道前因后果。手动截断 + 交接模板策略可以把对话按阶段"打包"，每个阶段有清晰的边界和总结，方便团队成员接力。

## 适用场景

✅ **什么时候用这个策略：**

- 多人协作完成同一个任务（如多人跟 AI 一起做方案）
- 任务需要交接（A 做一半交给 B 继续）
- 长周期项目，需要阶段性归档和回顾
- 团队需要追溯决策过程（为什么当时选了这个方案）
- 新人接手项目，需要快速了解上下文

❌ **什么时候不建议用：**

- 个人独立完成的小任务（没必要用）
- 实时协作（大家同时在线讨论，用全量更方便）

## 策略配置

### 阶段推进：手动截断（按阶段切分）

```json
{
  "strategy": "manualCut",
  "cutPoint": "stage_marker",
  "mode": "archived",
  "includeHead": 2,
  "stageSummary": true
}
```

**参数说明：**
- `cutPoint: "stage_marker"` — 遇到"阶段标记"消息时截断
- `mode: "archived"` — 归档模式，截断的内容不再发送但完整保留
- `includeHead: 2` — 始终保留任务目标和团队约定
- `stageSummary: true` — 每个阶段结束时自动生成阶段总结

### 交接模式：首尾保留 + 阶段摘要

```json
{
  "strategy": "headTail",
  "headReserve": 3,
  "tailReserve": 5,
  "middleStrategy": "stage_summary",
  "stageSummaryCount": 3
}
```

**参数说明：**
- `middleStrategy: "stage_summary"` — 中间内容只显示各阶段的摘要
- `stageSummaryCount: 3` — 保留最近 3 个阶段的摘要
- 新成员接手时，看一眼头部目标 + 阶段摘要 + 尾部最新进展，就能快速进入状态

## 使用技巧

### 1. 阶段标记怎么写？

每个阶段结束时，发一条结构化的"阶段标记"消息：

```
【阶段完成标记】
阶段名称：需求分析阶段
阶段结论：
1. 确定了核心功能范围（XXX、XXX、XXX）
2. 排除了 XXX 方向，原因是 XXX
3. 下一步进入方案设计阶段
关键决策人：张三
完成时间：2026-09-23
```

这条消息既是截断点，又是阶段总结的"锚点"。

### 2. 交接清单模板

当一个人把任务交给另一个人时，用这份清单确保信息完整：

| 交接项 | 说明 | 是否完成 |
|--------|------|---------|
| 任务目标 | 我们在做什么、为什么做 | ☐ |
| 当前进展 | 做到哪一步了 | ☐ |
| 已确定的结论 | 哪些决策已经定了 | ☐ |
| 已排除的方向 | 哪些路已经走过不通 | ☐ |
| 下一步计划 | 接下来要做什么 | ☐ |
| 风险/注意事项 | 有什么坑要避开 | ☐ |
| 相关资源 | 文档、链接、参考资料 | ☐ |

> 💡 这份清单放在对话头部，永久保留。任何人接手，先看清单就知道全貌了。

### 3. 多人协作的最佳实践

- **一人主导，其他人补充** —— 避免多人同时跟 AI 对话导致上下文混乱
- **定期阶段归档** —— 每个里程碑设一个截断点，生成阶段总结
- **决策留痕** —— 重要决策在对话中明确记录"为什么这么定"，方便日后追溯
- **新人上手** —— 给新加入的成员看头部的任务目标 + 各阶段摘要，5分钟了解全貌

### 4. 什么时候切换策略

- **日常推进** → 手动截断，按阶段归档
- **新人接手** → 首尾保留 + 阶段摘要，快速了解全貌
- **方案最终评审** → 全量上下文，让模型看到完整决策过程
- **项目复盘** → 全量上下文 + 导出完整记录，做复盘分析

## 效果案例

### 用户案例：技术方案团队协作

**背景：** 一个 3 人技术小组共同设计一个新系统的技术方案，历时 2 周。成员分工：A 负责架构设计，B 负责数据库设计，C 负责接口设计。

**使用前：**
- 3 个人各开各的对话，信息不同步
- 每次开会要花 30 分钟对齐各自的 AI 讨论结果
- 决策过程散落在 3 个对话里，追溯困难
- 总耗时 2 周，其中约 20% 的时间花在"信息同步"上
- Token 总消耗：约 60,000（3 个人重复讨论了很多内容）

**使用手动截断+交接模板后：**
- 共用一个对话任务，按阶段推进
- 每个成员负责自己的阶段，完成后归档，下一个人接手
- 阶段总结自动生成，任何人随时能看到全貌
- 总耗时 10 天（节约 4 天，约 29%）
- 信息同步时间从每天 30 分钟降到 5 分钟
- Token 总消耗：约 38,000（节省 37%）—— 因为没有重复讨论

**关键设置：**
- 头部永久保留：项目目标 + 技术约束 + 交接清单
- 每个设计阶段结束设截断点，生成阶段总结
- 成员切换时，新人看头部 + 阶段摘要 + 尾部最新进展，快速上手

**用户评价：**
> "以前团队用 AI 各用各的，信息散得到处都是。现在共用一个任务，按阶段推进，谁接手都能立刻进入状态。省下来的信息同步时间，比工具本身带来的效率提升还多。"
