# 内容创作场景：首尾保留 + 滑动窗口策略

## 策略简介

写文章、写文案、做内容策划时，最头疼的问题是：写着写着风格跑偏了，或者忘了最初的写作目标。首尾保留策略让开头的风格设定始终在位，配合滑动窗口让模型聚焦于最近几段内容的创作，既保持风格一致，又不让旧内容干扰新段落的产出。

## 适用场景

✅ **什么时候用这个策略：**

- 写长文（2000字以上），需要保持风格一致
- 公众号文章、技术博客、产品文案创作
- 分段落逐段打磨，每段单独讨论
- 有明确的风格要求（专业/口语/幽默等）
- 写作过程中会有多次修改和调整

❌ **什么时候不建议用：**

- 短文案、短段落（没必要用）
- 需要全文整体把控的润色阶段（建议用全量上下文）

## 策略配置

### 主策略：首尾保留 (headTail)

```json
{
  "strategy": "headTail",
  "headReserve": 4,
  "tailReserve": 6,
  "middleStrategy": "summary"
}
```

**参数说明：**
- `headReserve: 4` — 保留头部 4 条消息（写作目标 + 风格要求 + 读者画像 + 大纲）
- `tailReserve: 6` — 保留尾部 6 条消息（最近几段的创作和修改讨论）
- `middleStrategy: "summary"` — 中间内容只保留摘要，不发送完整内容

### 辅助策略：滑动窗口（分段创作时切换）

```json
{
  "strategy": "slidingWindow",
  "windowSize": 8,
  "includeSystemPrompt": true
}
```

在集中打磨某一段内容时，可以临时切换为滑动窗口，让模型完全聚焦于当前段落。

## 使用技巧

### 1. 头部放什么最有效？

头部 4 条消息建议按这个顺序放，效果最好：

| 序号 | 内容 | 重要性 |
|------|------|--------|
| 第1条 | **角色设定**：你是一个XX领域的资深作者 | ⭐⭐⭐⭐⭐ |
| 第2条 | **写作目标**：这篇文章要达成什么目的 | ⭐⭐⭐⭐⭐ |
| 第3条 | **风格要求**：文风、调性、用词偏好 | ⭐⭐⭐⭐ |
| 第4条 | **文章大纲**：整体结构和各段要点 | ⭐⭐⭐⭐ |

> 💡 这 4 条是文章的"定海神针"，永远保留在上下文中，风格就不会跑偏。

### 2. 不同文体的参数调整

| 文体类型 | 头部保留 | 尾部保留 | 窗口大小 |
|---------|---------|---------|---------|
| 技术文章 | 4-5 条 | 6-8 条 | 8-10 轮 |
| 营销文案 | 3-4 条 | 4-6 条 | 5-7 轮 |
| 小说/故事 | 5-6 条 | 8-10 条 | 10-12 轮 |
| 学术写作 | 5-6 条 | 6-8 条 | 8-10 轮 |
| 自媒体短文 | 2-3 条 | 4-5 条 | 4-6 轮 |

### 3. 创作不同阶段的策略切换

```
构思阶段 → 全量上下文（充分讨论，发散思维）
     ↓
初稿阶段 → 首尾保留（保持风格，逐段推进）
     ↓
打磨阶段 → 滑动窗口（聚焦当前段落精修）
     ↓
收尾阶段 → 全量上下文（整体通读润色）
```

### 4. 防止"越写越水"的小技巧

写作过程中，你可能会发现模型越写越敷衍、内容越水。这通常是因为：
1. 头部的风格要求被稀释了 → 用首尾保留，头部始终在位
2. 中间写了太多"好的""收到""明白了"之类的废话 → 用滑动窗口，让废话自动滑出
3. 模型觉得"差不多了"开始应付 → 手动截断，重新设定更具体的要求

## 效果案例

### 用户案例：技术长文创作

**背景：** 写一篇 3000 字的技术深度文章，主题是大模型上下文管理，读者是中高级开发者。

**使用前：**
- 创作过程：对话 28 轮，反复修改
- 问题：写到后半段风格明显变水，技术深度下降
- Token 消耗：约 9,600
- 改稿次数：5 次（因为风格跑偏要反复纠正）
- 总耗时：约 3 小时

**使用首尾保留策略后：**
- 创作过程：对话 20 轮，流畅推进
- 风格全程稳定，技术深度保持一致
- Token 消耗：约 5,300（节省 45%）
- 改稿次数：2 次（都是内容调整，不是风格问题）
- 总耗时：约 1.5 小时（节省一半时间）

**头部 4 条消息设置：**
1. 角色：你是一位有 10 年经验的后端架构师
2. 目标：写一篇关于大模型上下文管理的技术深度文章，让读者理解漂移和污染的原理
3. 风格：专业但不晦涩，有数据有案例，结构清晰，段落 3-5 句
4. 大纲：引言 → 问题现象 → 原理分析 → 解决方案 → 实战案例 → 总结

**用户评价：**
> "以前写长文，越写到后面越费劲，AI 好像忘了我要什么风格。用了首尾保留之后，从头到尾风格一致，就像有个写作搭档全程陪着，还从来不走神。"

### 另一个案例：公众号文案

**背景：** 写一篇产品推广文案，要求口语化、有感染力、面向普通用户。

**效果：**
- 风格一致性提升：从"写到一半就变味"到"全程保持调性"
- 修改次数减少：从平均 6-8 次降到 2-3 次
- 产出速度提升：约 40%
