# 产品设计场景：过期时间 + 首尾保留策略

## 策略简介

产品设计的对话有个特点——迭代快、变化多。今天定的方案，明天可能就推翻了。如果旧方案的讨论一直留在上下文里，模型会时不时"穿越"回去提旧方案。过期时间策略会自动清理"过时"的设计讨论，配合首尾保留确保核心目标始终在位。

## 适用场景

✅ **什么时候用这个策略：**

- 产品需求迭代快，方案经常调整
- 多版本设计方案对比，旧版本容易干扰
- 设计讨论会持续几天，每天都有新进展
- 需要保持产品核心目标不变，但细节不断演进
- 同时推进多个功能模块的设计

❌ **什么时候不建议用：**

- 一次性的简单设计（没必要用）
- 需要完整追溯设计决策过程（建议用全量+手动归档）

## 策略配置

### 主策略：过期时间 (expireTime)

```json
{
  "strategy": "expireTime",
  "expireMode": "duration",
  "expireMinutes": 360,
  "includeHead": 3,
  "gracePeriod": 30
}
```

**参数说明：**
- `expireMode: "duration"` — 按持续时间过期
- `expireMinutes: 360` — 6小时前的对话自动过期
- `includeHead: 3` — 前3条核心消息永远不过期（产品目标、用户画像、核心约束）
- `gracePeriod: 30` — 过期前30分钟提示，可手动延长

### 辅助策略：首尾保留（深度讨论时切换）

```json
{
  "strategy": "headTail",
  "headReserve": 4,
  "tailReserve": 10,
  "middleStrategy": "summary"
}
```

在深入讨论某个具体功能的设计细节时，临时切换为首尾保留，让模型同时看到产品目标和当前的设计讨论。

## 使用技巧

### 1. 过期时间怎么设？

| 设计节奏 | 推荐过期时间 | 原因 |
|---------|------------|------|
| 快速迭代（一天几轮） | 2-4 小时 | 上午的讨论下午可能就过时了 |
| 正常迭代（每天推进） | 6-8 小时 | 当天的讨论有效，昨天的自动清理 |
| 慢节奏（周级迭代） | 24-48 小时 | 一周内的讨论都保留 |

> 💡 建议从 6 小时开始试，根据实际效果调整。太快了信息丢得多，太慢了旧内容干扰。

### 2. 头部"永久保留"的内容放什么

产品设计场景下，这 3 条建议永远保留：

| 序号 | 内容 | 示例 |
|------|------|------|
| 第1条 | **产品定位** | "我们做的是一款面向开发者的AI上下文管理工具" |
| 第2条 | **目标用户** | "核心用户是每天用AI写代码的后端开发者" |
| 第3条 | **核心约束** | "无门槛使用、简洁高效、不做重功能" |

这三条是产品的"锚点"，不管方案怎么迭代，锚点不能变。

### 3. 多模块并行的技巧

如果你同时在设计好几个功能模块：

- 每个模块开一个独立的对话任务
- 每个任务用过期时间策略管自己的上下文
- 跨模块的共性问题，单独开一个任务讨论

这样比把所有模块混在一个对话里清晰得多。

### 4. 什么时候切换到首尾保留

- 进入某个功能的深度设计讨论时
- 需要回顾产品目标，确保设计不跑偏时
- 方案快定了，需要集中打磨细节时

## 效果案例

### 用户案例：SaaS 产品功能迭代设计

**背景：** 一款开发者工具的新功能设计，从需求讨论到方案定稿持续了 5 天，涉及功能定位、交互设计、技术可行性三个维度。

**使用前：**
- 5 天累计对话 60+ 轮
- 模型平均每天"穿越"2-3次（回到已经被推翻的方案）
- Token 消耗：约 35,000
- 每天早上第一件事：跟模型"复习"当前进展
- 最终定稿耗时：5 天

**使用过期时间+首尾保留后：**
- 5 天累计对话 45 轮
- 模型几乎不跑偏，始终聚焦当前方案
- Token 消耗：约 18,200（节省 48%）
- 每天打开对话，模型直接进入状态，不用"复习"
- 最终定稿耗时：3.5 天（节约 1.5 天）

**关键设置：**
- 过期时间：8 小时（当天的讨论有效，睡一觉昨天的自动清理）
- 永久保留：产品定位 + 目标用户 + 核心约束
- 深度讨论时切换为首尾保留，头部保留锚点，尾部保留当前设计

**用户评价：**
> "做产品设计最烦的就是方案变来变去，AI 还老揪着旧方案不放。用了过期时间之后，每天都是'新的开始'，但核心目标又没丢，设计效率高了很多。"
