# 产品设计：滑动窗口 + 灵感收集策略

## 策略简介

头脑风暴阶段，你会跟模型聊很多天马行空的想法——有的靠谱，有的不靠谱，有的只是随口一提。如果这些全部留在上下文里，到收敛阶段模型会被各种想法干扰。滑动窗口策略让过时的灵感自动"过期"，配合字段截取只保留有价值的创意点。

## 适用场景

✅ **什么时候用这个策略：**

- 产品创意发散、头脑风暴阶段
- 需要快速产生大量想法，然后逐步收敛
- 灵感来得快去得也快，不需要长期保留
- 多人脑暴接力，每人贡献一波想法
- 从"发散"到"收敛"的过渡阶段

❌ **什么时候不建议用：**

- 已经进入方案细化阶段（建议用首尾保留）
- 需要完整追溯创意来源（建议用全量上下文）

## 策略配置

### 发散阶段：滑动窗口

```json
{
  "strategy": "slidingWindow",
  "windowSize": 12,
  "includeSystemPrompt": true
}
```

**参数说明：**
- `windowSize: 12` — 保留最近 12 条消息。脑暴阶段节奏快，旧想法快速让位给新想法
- `includeSystemPrompt: true` — 始终包含脑暴目标和约束条件

### 收敛阶段：字段截取 + 首尾保留

```json
{
  "strategy": "headTail",
  "headReserve": 3,
  "tailReserve": 5,
  "middleStrategy": "key_points_only",
  "fieldFilter": ["idea", "highlight", "pros", "cons"]
}
```

脑暴结束进入收敛阶段时切换：头部保留目标，尾部保留当前讨论，中间只留下被标记为"有价值"的创意点。

## 使用技巧

### 1. 脑暴的正确打开方式

```
第1步：全量上下文，设定脑暴目标和规则
       例："我们来头脑风暴一下XXX功能的交互方式，目标用户是XXX，约束条件是XXX"
第2步：切换滑动窗口，开始发散
       想到什么聊什么，不用纠结，让想法飞一会儿
第3步：聊了10+轮后，让模型总结"目前最有价值的3个方向"
第4步：基于这3个方向继续深入
第5步：最终定稿时切换首尾保留
```

### 2. 给好想法"打标签"

脑暴过程中，遇到你觉得特别好的想法，主动标记一下：

> "这个方向不错，标记一下，后面重点讨论。"

字段截取策略会自动识别和保留这种被标记为"有价值"的内容。其他没被标记的想法，随着滑动窗口移动就自然消失了。

### 3. 窗口大小怎么选？

| 脑暴阶段 | 推荐窗口大小 | 原因 |
|---------|------------|------|
| 疯狂发散期 | 6-8 轮 | 想法更新快，窗口小一点不容易被旧想法束缚 |
| 初步筛选期 | 10-12 轮 | 需要对比多个想法，窗口大一点 |
| 聚焦深化期 | 12-15 轮 | 深入讨论少数几个方向，需要更多上下文 |

### 4. 什么时候"换挡"

- 感觉"聊不动了"，新想法越来越少 → 该缩小窗口，聚焦少数方向
- 觉得"有点乱了"，模型开始重复之前的想法 → 该收敛了，切换首尾保留
- 发现"某个方向特别有戏" → 手动截断，把其他方向隔离，全力深挖这个方向

## 效果案例

### 用户案例：新功能脑暴会

**背景：** 产品团队为一个新功能做脑暴，2个产品经理 + 1个设计师，用 AI 辅助创意发散，历时 3 小时。

**使用前：**
- 脑暴对话 40+ 轮
- 聊了很多方向，但越聊越散
- 到后面模型把各种想法混在一起，分不清哪些靠谱哪些不靠谱
- 收敛阶段花了 1 小时梳理"我们刚才都聊了啥"
- Token 消耗：约 15,000
- 最终产出：2 个可落地方向

**使用滑动窗口+字段截取后：**
- 脑暴对话 30 轮
- 发散阶段节奏快，旧想法自动让位给新想法
- 收敛阶段切换策略，只保留被标记为有价值的创意点
- 收敛只用了 20 分钟，清晰高效
- Token 消耗：约 7,500（节省 50%）
- 最终产出：3 个可落地方向（更多更优质）

**关键设置：**
- 发散期：滑动窗口 8 轮，快速迭代想法
- 每个好想法主动"打标签"
- 收敛期：切换首尾保留 + 字段截取，只看干货
- 最终定稿：全量上下文整理完整方案

**用户评价：**
> "以前脑暴完整理是最头疼的——聊了一大堆，最后不知道哪些是有用的。用了滑动窗口加标签的方式，发散的时候尽情想，收敛的时候自动过滤，效率高太多了。"
