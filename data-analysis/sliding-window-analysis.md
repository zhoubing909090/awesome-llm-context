# 数据分析场景：滑动窗口 + 过期时间策略

## 策略简介

数据分析对话的特点是：数据量大、时效性强、中间探索多。很多数据是"看一眼就过"的，没必要一直留在上下文里。滑动窗口让模型聚焦于最近的分析结果，过期时间自动清理过时数据，确保分析始终基于最新、最相关的信息。

## 适用场景

✅ **什么时候用这个策略：**

- 实时数据监控和异常分析
- 探索式数据分析（试了很多思路，大部分被排除）
- 数据时效性强，旧数据很快失去参考价值
- 多指标并行分析，每个指标独立讨论
- 周期性报表生成（日报、周报、月报）

❌ **什么时候不建议用：**

- 趋势分析、同比环比对比（需要历史数据，建议用首尾保留）
- 一次性的简单取数（没必要用）

## 策略配置

### 主策略：滑动窗口 (slidingWindow)

```json
{
  "strategy": "slidingWindow",
  "windowSize": 8,
  "includeSystemPrompt": true,
  "preserveHead": 2
}
```

**参数说明：**
- `windowSize: 8` — 保留最近 8 条消息（最近的分析结果和当前讨论）
- `includeSystemPrompt: true` — 系统提示始终保留
- `preserveHead: 2` — 额外保留头部 2 条（分析目标 + 数据口径说明）

### 辅助策略：过期时间 (expireTime)

```json
{
  "strategy": "expireTime",
  "expireMode": "duration",
  "expireMinutes": 120,
  "includeHead": 2
}
```

对于时效性极强的场景（如实时监控数据），设 2 小时过期，过时的数据自动清理。

## 使用技巧

### 1. 数据分析的"上下文噪音"从哪来？

数据分析对话里的噪音特别多，常见的有：

| 噪音类型 | 举例 | 处理方式 |
|---------|------|---------|
| 试探性查询 | "先看看这个数据对不对""试一下这个口径" | 滑动窗口自动滑出 |
| 被排除的假设 | "看来不是这个原因""这条路走不通" | 手动截断隔离 |
| 过期数据 | "昨天的数据是XXX""上周的趋势是XXX" | 过期时间自动清理 |
| 原始数据输出 | 大段的表格、JSON 数据 | 字段截取只保留结论 |
| 重复确认 | "对吗""是这样吗""再确认一下" | 滑动窗口自动清理 |

> 💡 数据分析场景下，上下文中 60%+ 的内容可能是"噪音"。裁剪之后，模型分析的质量会明显提升。

### 2. 不同分析场景的策略选择

| 分析类型 | 推荐策略 | 窗口大小 | 过期时间 |
|---------|---------|---------|---------|
| 实时监控 | 滑动窗口 + 过期时间 | 6-8 轮 | 1-2 小时 |
| 探索式分析 | 滑动窗口 + 手动截断 | 8-10 轮 | 4-6 小时 |
| 报表生成 | 首尾保留 + 字段截取 | — | — |
| 趋势对比 | 首尾保留 + 全量切换 | — | 按需切换 |
| 数据清洗 | 滑动窗口 | 10-12 轮 | 当天有效 |

### 3. 数据口径要放在头部

数据分析最容易出问题的地方是"口径不一致"。把下面这些放在对话头部，永久保留：

1. **数据来源** —— 从哪个系统取的数
2. **统计口径** —— 怎么定义的（如：日活是自然日还是 24 小时滚动）
3. **时间范围** —— 分析的是哪段时间的数据
4. **排除规则** —— 哪些数据要排除（如：测试数据、异常值）

口径对齐了，后面的分析才有意义。

### 4. 分析完成后的"收尾"流程

```
第1步：切换到全量上下文
第2步：让模型基于完整分析过程生成最终结论
第3步：用字段截取策略，只保留结论和关键数据
第4步：导出为分析报告
```

这样既保证了最终结论是基于完整分析过程的，又能把报告精简到只保留核心信息。

## 效果案例

### 用户案例：电商运营数据异常分析

**背景：** 某电商平台某天转化率突然下降，需要排查原因。涉及流量、商品、价格、活动、竞品等多个维度，分析过程持续了一整天。

**使用前：**
- 分析对话 35+ 轮
- 中间试了 6 个假设，5 个被排除
- 模型在第 20 轮之后开始"糊涂"——把已经排除的原因又拿出来说
- Token 消耗：约 18,000
- 排查耗时：约 6 小时
- 最终定位到了原因，但中间走了不少弯路

**使用滑动窗口+过期时间后：**
- 分析对话 25 轮
- 被排除的假设自动滑出窗口，不干扰后续分析
- 模型全程聚焦，回答精准
- Token 消耗：约 8,100（节省 55%）
- 排查耗时：约 3.5 小时（节约 2.5 小时，提升 42%）
- 分析结论更清晰，数据支撑更充分

**关键设置：**
- 滑动窗口：8 轮（最近的分析结果始终在位）
- 头部保留：分析目标 + 数据口径
- 过期时间：4 小时（上午的探索下午自动清理）

**用户评价：**
> "数据分析最怕的就是思路被旧数据带偏。用了滑动窗口之后，模型眼里只有'最新的数据和当前的问题'，分析效率高了不止一星半点。"
