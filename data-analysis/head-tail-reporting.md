# 数据分析：首尾保留 + 字段截取策略

## 策略简介

生成分析报告的时候，你需要模型看到完整的分析过程，但又不想让原始数据、试错过程占用太多 Token。首尾保留策略确保分析目标和最终结论都在位，字段截取策略把中间大量的原始数据输出精简为核心结论。

## 适用场景

✅ **什么时候用这个策略：**

- 生成数据分析报告（日报、周报、月报）
- 分析结论整理和输出
- 多维度数据汇总
- 需要保留分析逻辑，但精简数据体量
- 向领导/团队汇报的最终版分析

❌ **什么时候不建议用：**

- 探索式分析阶段（建议用滑动窗口）
- 需要看到原始数据明细（用全量上下文）

## 策略配置

### 报告生成：首尾保留 + 字段截取

```json
{
  "strategy": "headTail",
  "headReserve": 3,
  "tailReserve": 5,
  "middleStrategy": "field_cut",
  "fieldFilter": {
    "assistant": ["conclusion", "key_data", "insight", "recommendation"],
    "user": ["question", "requirement"]
  }
}
```

**参数说明：**
- `headReserve: 3` — 保留头部 3 条（分析目标 + 数据口径 + 时间范围）
- `tailReserve: 5` — 保留尾部 5 条（最终结论和建议）
- `middleStrategy: "field_cut"` — 中间内容按字段裁剪，只保留结论、关键数据、洞察和建议
- `fieldFilter` — 具体定义哪些字段要保留

### 草稿阶段：全量上下文（可选）

```json
{
  "strategy": "full",
  "note": "第一遍生成报告草稿时用全量，确保不遗漏"
}
```

第一遍写报告草稿时可以先用全量，让模型看到所有分析过程。生成草稿后切换为首尾保留+字段截取，再让模型精修和优化。

## 使用技巧

### 1. 一份好分析报告的"三段式"

| 部分 | 内容 | 对应策略区域 |
|------|------|------------|
| 头部 | 分析背景 + 数据口径 + 核心结论摘要 | 头部保留区 |
| 中部 | 详细分析 + 数据支撑 + 各维度拆解 | 字段裁剪区（只保留关键数据和结论） |
| 尾部 | 最终结论 + 行动建议 + 下一步计划 | 尾部保留区 |

头部和尾部是读者最关心的，必须完整保留。中间的大量分析过程和原始数据，只留精华就行。

### 2. 字段截取的"保留清单"

生成报告时，建议保留这些类型的内容：

| 保留类型 | 举例 | 为什么保留 |
|---------|------|-----------|
| 结论 | "转化率下降的主要原因是XXX" | 报告的核心价值 |
| 关键数据 | "日活下降了15%，其中移动端下降23%" | 支撑结论的数据 |
| 洞察发现 | "发现一个有趣的现象：新用户留存反而上升了" | 有价值的意外发现 |
| 行动建议 | "建议立即排查XXX，预计能恢复80%的转化" | 可落地的下一步 |
| 异常说明 | "数据异常是因为XXX活动，已排除" | 必要的解释说明 |

**这些可以裁掉：**
- 大段的原始数据表格
- 试探性的查询和被排除的假设
- 重复确认和反复验证的过程
- 模型的思考过程（"让我想想……""可能是……"）

### 3. 报告生成工作流

```
第1步：全量上下文 → 生成报告初稿
       （让模型看到所有分析过程，确保不遗漏）
第2步：切换首尾保留+字段截取 → 让模型精简报告
       （"基于以上分析，帮我生成一份精简版报告，只保留核心结论和关键数据"）
第3步：人工审阅 → 调整结构、补充细节
第4步：切换全量上下文 → 最终核对数据准确性
第5步：字段截取模式 → 导出最终版报告
```

### 4. 定期报告的模板化

如果是日报/周报/月报这种定期报告，可以：

1. 把报告模板放在对话头部（永久保留）
2. 每次生成报告时，模型自动套模板
3. 数据部分用字段截取自动填充
4. 结论部分由模型基于分析生成

模板越固定，生成效率越高。

## 效果案例

### 用户案例：周报自动化生成

**背景：** 数据分析师每周要产出一份运营周报，包含 8 个核心指标的趋势分析、异常说明、下周预测。以前每周一上午专门写报告，耗时约 3 小时。

**使用前：**
- 每周一上午跟 AI 讨论数据、写报告
- 对话里塞满了各种原始数据查询、中间计算、试错过程
- 写报告前要先"整理思路"，把关键数据挑出来
- 写报告过程中 Token 消耗大（大量数据来回传）
- 总耗时：约 3 小时/周
- 报告质量：数据完整但不够精炼，经常被说"太长了没人看"

**使用首尾保留+字段截取后：**
- 头部固定：周报模板 + 指标定义 + 时间范围
- 分析过程用滑动窗口，只保留最近的分析结果
- 生成报告时切换首尾保留+字段截取，自动生成精简版
- Token 消耗减少约 60%（原始数据不再反复传输）
- 总耗时：约 1 小时/周（节省 2 小时，提升 67%）
- 报告质量：结构清晰、重点突出，反馈变好

**关键设置：**
- 分析阶段：滑动窗口，高效探索
- 报告阶段：首尾保留+字段截取，精简输出
- 头部固定模板，每次直接套用
- 最终核对：切全量确认数据准确性

**用户评价：**
> "以前写周报最烦的就是从一堆数据里挑重点。有了字段截取之后，AI 自动帮我把干货提炼出来，我只需要调整一下措辞和结构，效率提升太明显了。"
